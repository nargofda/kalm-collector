# kalm-collector

캄134(제주 표선)의 **네이버 공개 예약 페이지**를 읽어, 날짜별 객실 판매/마감 상태를
예약 달력(`funsoft.co.kr/kalm`)으로 보내는 수집기입니다.

## 무엇을 하나

- 네이버 플레이스의 **공개 객실 페이지**를 날짜만 바꿔가며 엽니다. **로그인하지 않습니다.**
- 객실 카드의 "예약마감" 표시를 읽어 `open` / `closed` 로 기록합니다.
- 결과를 달력 서버로 보냅니다. 여러 판매 채널이 어긋났는지(한쪽만 마감) 그쪽에서 판정합니다.

## 왜 만들었나

같은 객실을 네이버와 여기어때에서 각각 팔다 보면, 한쪽에서 팔린 날짜를 다른 쪽에서
닫지 않아 중복 예약이 납니다. 채널매니저를 쓰지 않는 소규모 숙소에서 그걸 눈으로
확인하려고 만들었습니다.

## 실행

```bash
npm install
npx playwright install --with-deps chromium

node collect.js --days 3 --dry     # 서버로 보내지 않고 화면에만
KALM_KEY=... node collect.js --days 10
```

### 설정 (환경변수)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `KALM_KEY` | (필수) | 달력 서버로 보낼 때 쓰는 열쇠 |
| `KALM_API` | `https://funsoft.co.kr/kalm/api.php` | 보낼 주소 |
| `KALM_PLACE` | `2033306049` | 네이버 플레이스 업소 번호 |
| `KALM_ROOMS` | `Garden,Tree` | 객실 이름 (쉼표 구분) |
| `KALM_NIGHTS` | `2` | 조회 박수 (최소 숙박일수에 맞춘다) |
| `KALM_GAP` | `1500` | 날짜 사이 간격(ms) |

## 자동 실행

`.github/workflows/collect.yml` 이 가까운 날짜(10일)는 10분마다, 먼 날짜(11~45일)는
하루 두 번 수집합니다. 깃허브 예약 실행은 정시에 오지 않고 20~30분씩 밀릴 수 있습니다.

저장소에 60일간 변경이 없으면 예약 실행이 자동으로 꺼지므로, 가끔 커밋이 필요합니다.
